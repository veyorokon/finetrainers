  Separation of Concerns

  Level of Abstraction

  - Elements: Define what inputs to use (including virtual ones like mask)
  - Processors: Define how to process inputs
  - Element-Processor Config: Define element-specific processing parameters
  - tensor_combinations: Define how to organize processor outputs into model inputs

  Framework Alignment

  - ProcessorMixin: All processors follow this interface
  - ConfigMixin: All configurations follow this pattern
  - Batch Processing: Maintain batch processing capabilities
  - Virtual Elements: Support elements with no physical files

  Design Principles

  1. Framework Consistency: Follow established patterns from existing trainers
  2. Configuration-Driven: Behavior controlled through JSON, not hardcoding
  3. Clean Separation: Keep concerns clearly separated in both code and config
  4. Flexibility: Support various mask patterns through frame conditioning types
  5. Elegance: Simple implementation with minimal code changes

  Benefits

  - Removes hardcoded behavior for greater experimental flexibility
  - Explicit tensor combination control through configuration
  - Clean separation between what processors do and how outputs are combined
  - Maintains compatibility with A2 inference approach
  - Enables more advanced configurations for future research

  This approach ensures the implementation is both powerful and elegant, preserving the design principles of the
  framework while adding the flexibility needed for E2V training.
