# LoRA Training Strategies for E2V Model Customization

## Overview

This document outlines strategies for effective LoRA (Low-Rank Adaptation) training of the Elements-to-Video (E2V) model. It provides a technical breakdown of module targeting approaches, justifications based on model architecture, and practical implementation guidance for different use cases.

## Model Architecture Analysis

Understanding the E2V/A2 model architecture is essential for effective LoRA targeting. The model processes data through two primary pathways:

### Dual Conditioning Pathways

1. **Spatial Pathway (VAE-based)**:
   - Processes reference images through VAE encoder
   - Creates a "mini-video" of reference frames
   - Encodes spatial details and structural information
   - Concatenated with video latents along channel dimension
   - Primary entry point: `patch_embedding` (3D Conv layer)

2. **Semantic Pathway (CLIP-based)**:
   - Processes reference images through CLIP vision encoder
   - Extracts high-level semantic understanding
   - Projected to match text embedding dimensions
   - Integrated via cross-attention mechanism
   - Primary entry points: `add_k_proj` and `add_v_proj`

### Key Model Components

```
# Simplified component flow
Inputs → patch_embedding → transformer_blocks[0..N] → Output Projection
                      ↑
                      └── condition_embedder (time, text, image)
                                ↑
                                └── CLIP embeddings via add_k_proj/add_v_proj
```

From code analysis (A2/models/transformer_a2.py), the following components are identified:

```python
# In WanAttnProcessor2_0.__call__
if encoder_hidden_states_img is not None:
    key_img = attn.add_k_proj(encoder_hidden_states_img)  # CLIP pathway entry
    value_img = attn.add_v_proj(encoder_hidden_states_img)
    # ... process and integrate with main flow

# In A2Model.forward
hidden_states = self.patch_embedding(hidden_states)  # Spatial pathway entry
# ... process conditions and images
```

References in pipeline_a2.py confirm this dual-pathway approach, with VAE-encoded latents concatenated with noisy video latents at the channel dimension, and CLIP embeddings passed separately.

## LoRA Training Strategies

Based on this architecture analysis, we propose three strategic approaches for LoRA training:

### Strategy 1: Specialized Non-Overlapping LoRAs

This approach creates completely independent adapters for different aspects of generation:

#### Control-Specific LoRA
```
"patch_embedding"
```
- **Justification**: This module is the entry point for spatial conditioning, directly handling how control signals are encoded and processed.
- **References**: The `prepare_latents` function in pipeline_a2.py (lines 288-394) shows how control conditions are encoded through VAE and concatenated before passing through patch_embedding.
- **Use Cases**: New control types (canny edges, segmentation maps, depth maps, first/last frame conditioning)

#### Style/Aesthetic LoRA
```
"(add_k_proj|add_v_proj)"
```
- **Justification**: These modules exclusively handle the CLIP embeddings that provide high-level semantic understanding and style information.
- **References**: Lines 570-575 in pipeline_a2.py show how CLIP embeddings are processed and passed to the model via these projections.
- **Use Cases**: Visual style (cinematic, anime, photorealistic), lighting adjustments, color grading effects

#### Core Generation LoRA
```
"(transformer_blocks|single_transformer_blocks).*(to_q|to_k|to_v|to_out.0|ff.net.0.proj|ff.net.2)"
```
- **Justification**: These modules handle the core generative process after conditioning is applied.
- **References**: WanTransformerBlock in transformer_a2.py shows how these components process information in each block.
- **Use Cases**: General quality improvements, coherence enhancements, universal adjustments

### Strategy 2: Product-Focused Base LoRA

For product-centric video generation without humans, we recommend:

```
"(transformer_blocks|single_transformer_blocks).*(to_q|to_k|to_v|to_out.0)|patch_embedding|(add_k_proj|add_v_proj)"
```

- **Justification**: This comprehensive pattern targets both spatial and semantic pathways while focusing on attention mechanisms crucial for product representation.
- **Deliberately Excludes**: Feedforward networks (`ff.net.0.proj|ff.net.2`) to reduce parameter count.
- **References**: The A2 paper (sections 2.2-2.3) discusses how both spatial and semantic features are essential for composition quality.

This approach provides several advantages for product-focused generation:

1. **Complete Conditioning Coverage**:
   - Spatial pathway (via patch_embedding): Essential for capturing detailed product structure
   - Semantic pathway (via add_k_proj/add_v_proj): Critical for cinematic style application

2. **Focused Attention Refinement**:
   - Self-attention mechanisms handle spatial relationships between products and environments
   - Cross-attention integrates style information into the generation process
   - Attention to detail is especially important for product features, textures, and branding

3. **Parameter Efficiency**:
   - By excluding feedforward networks, the LoRA focuses only on the most impactful modules
   - Reduces training time and resource requirements without significantly impacting quality

### Strategy 3: Hierarchical LoRA Combination

This strategy builds on the product-focused base to create a modular ecosystem:

1. **Base LoRA**: Product-centric foundation using Strategy 2
2. **Style Variants**: Additional small LoRAs targeting only `"(add_k_proj|add_v_proj)"` for different moods/styles
3. **Category Specialists**: Additional small LoRAs targeting only `"patch_embedding"` for different product categories

This hierarchical approach allows for:
- Maximum flexibility during inference
- Efficient training of specialized components
- Mix-and-match capabilities without interference
- Independent scaling of each component's influence via LoRA alpha

## Practical Implementation

### Command Line Usage

When training LoRAs with the E2V trainer, use the `--target_modules` parameter:

```bash
python train.py \
  --config=example/training.json \
  --training_type=e2v \
  --use_peft=True \
  --rank=32 \
  --target_modules="(transformer_blocks|single_transformer_blocks).*(to_q|to_k|to_v|to_out.0)|patch_embedding|(add_k_proj|add_v_proj)"
```

For style-only LoRAs:
```bash
python train.py \
  --config=example/training.json \
  --training_type=e2v \
  --use_peft=True \
  --rank=16 \
  --target_modules="(add_k_proj|add_v_proj)"
```

### Loading Multiple LoRAs

During inference, multiple LoRAs can be loaded simultaneously:

```python
# Load base product LoRA
pipe.load_lora_weights("path/to/product_base_lora", adapter_name="base")

# Add style LoRA with specific scaling
pipe.load_lora_weights("path/to/cinematic_style_lora", adapter_name="style")

# Set different scaling for each adapter
pipe.set_adapters(["base", "style"], adapter_weights=[1.0, 0.8])

# Generate with combined adapters
pipe(prompt="Luxury watch on marble surface with dramatic lighting", 
     image_vae=[product_image, background_image])
```

## Recommendations and Best Practices

1. **Experiment with rank values**:
   - Larger rank (32-64) for comprehensive base LoRAs
   - Smaller rank (8-16) for specialized style/category LoRAs

2. **Data considerations**:
   - For product-centric training: Focus on high-quality product videos with diverse angles and movements
   - For style training: Curate datasets with consistent aesthetic qualities
   - For control training: Ensure paired data with appropriate control signals

3. **Validation approach**:
   - Test combinations of LoRAs with different alpha values
   - Validate that non-overlapping LoRAs can be combined without interference
   - Compare different targeting strategies on the same dataset

4. **Potential issues**:
   - Some module patterns may need adjustment based on specific model versions
   - Very small LoRAs might have limited impact on generation
   - Excessively large LoRAs might overfit to training data
